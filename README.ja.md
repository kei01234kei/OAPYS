# OAPYS

[English](README.md) | **日本語**

**Offensive Attack to Protect Your Systems** の公開 frontend。Next.js App Router / TypeScript を使用します。
backend は独立した private リポジトリで管理し、このリポジトリには含めません。

## ローカル開発

Node.js 24 と npm を使用します。`.node-version` / `.nvmrc` に初期環境のバージョンを記録しています。

```sh
cp .env.example .env.local
npm ci
npm run dev
```

http://localhost:3000 を開きます。backend がなくてもグラフ画面を操作できます。backend の接続状態は通知から確認できます。
`GET /api/health` は backend 接続時に 200、未接続時に 503 を返します。

```sh
npm run lint
npm run typecheck
npm run build
```

`BACKEND_URL` は Next.js サーバーのみが使用します。秘密情報を `NEXT_PUBLIC_*` に設定しないでください。
ブラウザーから backend へ直接接続しないため、開発用 CORS 許可は不要です。
ヘルスチェックに加え、管理者セッション、クラウド接続・同期、DNS 所有確認、HTTP(S) プローブを API 契約に沿って実装しています。backend の設定とクラウド権限は別途必要です。

## Security graph ワークスペース

ワークスペースは App Router の独立したページに分かれ、共通のサイドメニューで移動します。

| URL | ページ |
| --- | --- |
| `/` | 概要：サマリーと最大 5 件の優先リスク |
| `/assets` | 管理対象：チェック状況、システム構成図、対象の詳細 |
| `/risks` | リスク：検索、重要度フィルター、対象資産へのリンク |
| `/investigations` | AI 調査：質問、進捗、レポート、根拠、履歴 |
| `/settings` | 設定：管理者ログイン、クラウド接続、診断対象 |

`/settings?tab=targets` で診断管理を直接開けます。資産へのリンクは、対象資産・グラフ表示・詳細タブを URL に保持します。通常のページ移動では共通レイアウトが表示環境・グラフの状態・AI 調査を維持し、質問や進行中の調査も引き継ぎます。再読み込み時は有効な管理者セッションを確認して実環境の資産を再取得し、保存済みの調査レポートは履歴から参照できます。リスク一覧とグラフの絞り込みは独立しています。

ヘッダーの表示モードで **OS に合わせる／ライト／ダーク** を選択できます。初期状態は OS の外観設定に従い、画面を開いたままの OS 設定変更にも追従します。手動の選択はブラウザに保存され、タブ間でも同期します。「OS に合わせる」で自動切り替えに戻せます。ワークスペース・グラフ・接続ダイアログ全体が両モードに対応しています。

UI は英語と日本語に対応しています。ブラウザの最優先言語（既定では OS の言語設定に従います）が日本語なら日本語、それ以外は英語で表示します。文言は `src/i18n/` にあります。backend が返す文字列（エラー、ジョブイベント、AI の出力）は受け取ったまま表示します。

画面ではサーバー・データベース・ストレージなどを「管理対象」、カバレッジを「管理対象のチェック状況」と呼びます。実環境の「システム構成図」は API が返す構成上の関係を示し、通信到達性や攻撃の成立は検証していません。架空の攻撃経路は「攻撃経路（デモ）」と区別します。

UI に、架空のサンプルデータを使った 2 種類の操作可能なグラフを実装しています。

- **Asset coverage graph**：AWS・GCP の資産構成、診断状況、重要度フィルター、検索、資産詳細。
- **Exploration graph**：外部公開、ワークロード、ストレージ、データベースをつなぐ 2 つの攻撃経路例。
- ノード選択、ドラッグ移動、拡大・縮小・全体表示、絞り込み後のグラフの JSON 出力、関連経路へ移動するリスク一覧。

デモの 11 ノードはワークスペース、2 つのクラウド環境、8 リソースで構成し、7 リソースを診断済み（87.5%）として表示します。優先リスク 3 シナリオと各資産の検出件数は別の集計です。

「実環境に切替」から管理者ログインし、AWS・GCP 接続の登録・同期、対象ホストの DNS 確認、権限を確認した HTTP(S) プローブ、承認取消・接続解除ができます。実環境グラフは API の資産・関連・検出結果を使い、証跡と推奨対応を表示します。クラウドの秘密鍵はブラウザーに入力しません。

サーバー環境に `BACKEND_API_TOKEN`（32 文字以上）を設定し、backend 側に同じ管理用認証情報を設定します。実際の AWS・GCP 接続には backend 側のロール・認証・読み取り権限が必要です。すべての画面は管理者セッションが必要で、未ログインの訪問者は `/login` へ転送されます。そのためワークスペースの利用にはトークン設定が必須です。ログイン後は実データを登録するまでデモを表示し、モード切替でデモと実環境をいつでも切り替えられます。実環境の範囲、認証、エンドポイント、カバレッジの定義は [API 契約](docs/security-api.ja.md) を参照してください。

## Docker（frontend 単体）

```sh
docker build -t oapys-frontend:dev .
docker run --rm -p 127.0.0.1:3000:3000 oapys-frontend:dev
```

backend と併せて起動する開発者向け Compose は、private backend リポジトリ側にあります。
公開 frontend は private リポジトリの取得なしで開発できます。

## 依存関係について

初期環境の外部ネットワーク制限のため、キャッシュで検証可能な Next.js 16.2.6 / React 19.2.4 を固定しています。
最新のセキュリティ更新の適用確認は未完了です。本番公開前に、ネットワーク接続可能な環境で公式アドバイザリを確認し、Next.js / React とランタイムを更新して再検証してください。

```sh
npm install --save-exact next@latest react@latest react-dom@latest
npm install --save-dev --save-exact eslint-config-next@latest
npm audit
npm run lint
npm run typecheck
npm run build
```

参考: [Next.js installation](https://nextjs.org/docs/app/getting-started/installation)、[公式セキュリティ情報](https://nextjs.org/blog)。

## AI 主導の調査

まず問いを伝え、説明を読んでからグラフ上の根拠を確認する流れに対応します。質問入力、AI の設定状態、データ送信の確認、進捗、履歴、根拠付きレポート、調査時点の証跡、不明点、関連資産の強調を用意しています。接続先は backend の管理者が別途設定し、既定の AI サービスは選びません。[AI の API 契約](docs/security-api.ja.md#ai-調査の契約) を参照してください。デモでは仕組みを表示し、モデルは呼びません。
